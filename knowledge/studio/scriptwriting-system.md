# Studio Short-Form Scriptwriting System

## For future Claude
This note is the operational screenplay grammar for 4–12 second hooks, intros and B-roll inserts inside longer talking-head videos. It is a reviewed clean-room synthesis, not a universal platform formula. Verify current platform specifications and use owned experiments before making performance decisions.

## Story premise contract

Write these fields before writing dialogue or choosing images:

| Field | Required question | Failure signal |
|---|---|---|
| Audience forcing moment | What happened just before the viewer arrived? | generic topic announcement |
| Protagonist/POV | Who wants something now? | no actor or decision owner |
| Objective | Which visible state must change? | abstract “improve/optimize” goal |
| Obstacle | What physically or procedurally prevents it? | vague “complexity” |
| Stakes | What becomes slower, riskier, costlier or less trustworthy? | melodrama without consequence |
| Scene | Where can conflict and change be seen? | decorative location |
| Trigger prop | Which object exposes the changed situation? | narration-only inciting event |
| Hero verb | What can the actor visibly do? | “understands,” “leverages,” “transforms” |
| Persistent target | Which object/state survives every relevant cut? | new unrelated object each second |
| Proof prop | What can be inspected? | generic checkmark or claim card |
| Limitation | Where does evidence stop? | implied universal success |
| Payoff | What exact opening question is answered? | CTA replaces resolution |
| Handback | How does the visual return to A-roll? | abrupt promotional ending |

Core sentence:

> Because a concrete obstacle changes the situation, an identifiable actor performs an observable action on a persistent target, producing a bounded changed state that the viewer can inspect through proof and limitation.

## Default six-second beat sheet

| Second | Narrative state | Image/action requirement | Emotional job | Cut justification |
|---:|---|---|---|---|
| 0–1 | hook / inciting change | anomaly, consequence, contradiction or incomplete action already visible | surprise or recognition | viewer can form a precise question |
| 1–2 | orientation | actor, target, objective and geography share one readable scene | comprehension | establishes what/where/who |
| 2–3 | obstacle / stakes | resistance blocks the target and consequence becomes inspectable | concern | changes predicted outcome |
| 3–4 | decision / action | one physical verb changes the target | agency | shows causal attempt or mechanism |
| 4–5 | proof | receipt, trace, example, comparison, timestamp or test appears | cautious confidence | separates evidence from assertion |
| 5–6 | limitation + payoff + handback | boundary remains visible while changed target resolves opening and returns to A-roll | bounded relief | closes the same information gap |

For 10–12 seconds, split action, proof, limitation and handback into longer states. For >15 seconds, chain multiple complete events; do not stretch one event with filler.

## Hook selection logic

| Viewer state | Preferred family | Opening image | Required closure |
|---|---|---|---|
| already feels urgency | in medias res | action or consequence already underway | explain what changed and boundary |
| wants outcome first | result rewind | resolved target | reveal decisive step without bait-and-switch |
| has symptom but not cause | diagnostic mystery | anomalous trace | test clue and show bounded diagnosis |
| repeats an obvious mistake | failed-attempt correction | failed attempt | failure yields corrective information |
| faces abstract mechanism | object metaphor | tangible system/prop | map metaphor back to real workflow |
| needs finite procedure | countdown ladder | numbered progress promise | last rung is proof or constraint, not hype |
| needs contrast | before/after transformation | simultaneous states | show converting action, not only states |
| doubts a claim | proof reveal | empty evidence slot | fill with inspectable proof and limit |
| holds conflicting beliefs | contradiction resolution | two incompatible facts | reveal missing condition/distinction |
| follows a narrated process | process handback | input entering process | return with checked output and rule |

## Emotional design

Default ethical arc: `recognition → concern → agency → cautious confidence → bounded relief`.

- Recognition comes from a plausible forcing moment, not a stereotype.
- Concern is attached to a visible consequence, not vague fear.
- Agency appears when the hero chooses or performs a bounded action.
- Confidence is supported by proof, never merely triumphant music or typography.
- Relief remains bounded by the stated limitation.

Permitted entry/exit pairs include curiosity→clarity, confusion→orientation, frustration→agency, skepticism→cautious confidence, overload→control, risk awareness→guarded safety, surprise→understanding, and tension→bounded relief.

Avoid shame→submission, fear→false certainty, envy→purchase urgency, outrage without resolution, manufactured scarcity and unsupported social proof.

## Technical-detail ladder

1. Show the concrete problem object.
2. Name one mechanism verb.
3. Depict the target state changing.
4. Isolate the proof object.
5. State the boundary.
6. Return to the audience’s task.

Translate abstractions into visible operations:

- governance → a gate waits for a review token;
- provenance → a line connects a claim to a dated source tile;
- freshness → a timestamp appears before a metric;
- orchestration → work objects route through a controlled junction;
- memory → a request retrieves one labeled prior record;
- safety → an exception leaves the normal lane and reaches a human;
- contradiction → two states stay visible until a missing condition appears;
- ownership → an anonymous task gains a named decision lane.

## B-roll and camera rules

Every cutaway gets one function: `establish_context`, `concretize_abstraction`, `demonstrate_process`, `prove_state`, `contrast`, `attention_reset`, `emotional_texture`, or `orient_interface`.

- Push in to isolate an anomaly.
- Pull out to reveal geography or the resolved whole.
- Pan/match movement to preserve an action across space or cuts.
- Rack focus to transfer attention from mechanism to proof.
- Lock the camera for comparison, obstacle or evidence inspection.
- Use discontinuity only when goal, location, object, time or evidence truly changes.

If a visual does not change what the viewer knows, keep A-roll.

## Captions and sound

- Keep captions, UI, charts and labels editable.
- Give each beat one principal cognitive job: locate, read, compare, infer or verify.
- Do not start dense copy on the same instant as a complex proof reveal.
- Use sound accents for state changes; silence can protect proof or limitation.
- Maintain a conservative 9:16 inset until current placement UI is verified.

## Quality gate

A script fails if any answer is “no”:

1. Can the opening be understood as a visible question?
2. Is the viewer job and forcing moment specific?
3. Does the same target persist through obstacle, action and proof?
4. Does action causally address the obstacle?
5. Does each cut add information?
6. Is proof inspectable and different from a claim?
7. Is the limitation explicit where business, safety or reliability outcomes could be implied?
8. Does payoff answer the opening before CTA?
9. Is the result clean-room original?
10. Are performance statements labeled as hypothesis until owned tests exist?
