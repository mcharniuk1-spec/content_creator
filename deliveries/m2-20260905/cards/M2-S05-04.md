# M2-S05-04 — Test the same task before changing tools

M2 Radar · English · 50 seconds · 9:16 · **Candidate; independent and owner review pending.**

**Viewer task:** Evaluate a new AI assistant for weekly updates. **Friction:** Comparisons change both the tool and task, hiding whether the result is useful. **Human decision:** The process owner decides whether a candidate tool meets a fixed checklist.

## Three openings

1. A tool demo is a reason to test, not switch.
2. Keep the task the same when you compare AI tools.
3. That new assistant looks impressive. Can it handle your ordinary update?

## Spoken script

A tool demo is a reason to test, not switch. Suppose your repeated task is turning weekly notes into an update. Keep one fictional input ready. Run that same input through a candidate tool using the same instructions and required output. Check three things: did it preserve the facts, show missing information, and leave an editable draft? Record the result beside the tool version and the date. Include the part that failed. A polished answer is not the whole test. Someone still has to review and maintain the workflow. If it misses a requirement, adjust the task or reject this candidate. You do not need to switch. Keep one example and one checklist. Use them for your next tool evaluation.
