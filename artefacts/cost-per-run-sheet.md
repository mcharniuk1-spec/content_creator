# Cost per run

A tool's monthly price means nothing until you divide it by the number of times the job actually runs.

| tool | monthly price | the job it does | runs per week (count it, do not guess) | runs per month | price per run | hours per run it replaces | worth it? |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

Rules:
1. Count runs for two real weeks before deciding. Most "daily" jobs run three times a week.
2. Price per run = monthly price ÷ runs per month. Compare with what the run costs you by hand (your hourly rate × minutes).
3. Usage-based tools (API, credits): write the cap and the guard that stops spending without a yes. Our own ledger: 889 requests, $0.02 each, $17.78 for the whole research corpus, cap set in code.
4. Re-run the sheet when a plan changes price or when the job stops running.
5. The $20 plan is the reference. Pay $200 only when you hit limits and can count the hours.
