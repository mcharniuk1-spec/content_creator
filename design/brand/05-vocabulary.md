# 05. Vocabulary and naming

## Words and constructions we use

| Word or construction | What it means for us |
|---|---|
| repeated workflow | The unit of work M2 starts from. A workflow run more than once a week with recognizable inputs. |
| repeated task | One task inside a workflow. Used only in that literal sense, never as the unit M2 starts from. |
| fragmentation | The workflow broken into fragments, each with its input, output, decision and risk, before any tool is chosen. |
| AI boundary | The line between what the model does and what a person keeps. Named in every workflow. |
| human review | The named approval step before output leaves the team. |
| first test | The first small run on real work, with a result we are willing to publish. |
| workflow | One connected sequence that produces a specific output. Not a tool, not a platform. |
| we tested | We ran it ourselves, on our own process, for a stated period. |
| we built | We assembled the version being shown, and can show the file. |
| this broke | A specific step failed, and we name the input that caused it. |
| verdict | Our labeled conclusion: KEEP, TEST or KILL, with a reason. |
| what we did not automate | The deliberate human-owned step, and why it stays human. |
| WAS / NOW / SAVED | The only way we present a time or volume number. |
| on our own process | The origin of every internal number. |
| client result | Reserved for a real client pilot with an agreed baseline and metric. |
| experiment | What an internal build is, until a client pilot exists. |
| process owner | The named person responsible for the work, before and after AI. |
| cost of error | How bad it is when the model is wrong. Decides whether we automate at all. |
| worth a pilot | Our strongest honest recommendation. |
| not yet | An acceptable, publishable conclusion. |

## Naming rules

- **M2 Lab.** Capital M, digit 2, space, capital L. Never `M2Lab`, `m2 lab`, `M2lab`.
- **m2lab.ai** is the username and is always lowercase.
- **M2 Radar, M2 Builds, M2 Teardowns.** Both words capitalized, with `M2` in front on
  first mention in any piece. After first mention, `Radar`, `Builds`, `Teardowns`
  are allowed. Builds and Teardowns keep the plural as the format name. A single
  episode is "a Teardown" or "a Build".
- **On-screen format tags** are uppercase with the episode number: `RADAR / 04`,
  `BUILD / 03`, `TEARDOWN / 05`.
- **KEEP, TEST, KILL** are always uppercase, in copy and on screen. `M2 VERDICT` is
  always uppercase.
- **CURRENT, AI LAYER, VERDICT** are uppercase when used as the three columns of the
  process scheme.
- **Michael & Max**, in that order, with an ampersand. Michael in public copy,
  Max in public copy. Never reorder, never abbreviate to initials.
- **Spelling is American English** across all published copy.
