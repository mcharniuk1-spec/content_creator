# Partner timer integration

This directory contains the independently reviewed replacement for Radar's root `server_entry.py` and matching configuration templates. Copy the entry to the Radar repository root with the shared engine modules; it is not intended to be run from this nested directory. Independent R4 review accepted owner-controlled integration testing. The partner-host smoke test remains an acceptance step before activation.

The timer first runs the existing export or completed legacy snapshot through Signal. Default behavior remains replay only. An optional `media_job_config` path in the private timer configuration invokes the same serial acquisition/local ASR/frame dispatcher after all deterministic replay stages pass, the controller verifies its event chain and artifact hashes, and the exact Reel export is bound to a completion receipt. Media processing does not call HikerAPI. No Git pull, install, schedule change, semantic model, Notion write or publishing action is hidden in the timer.

The timer configuration now requires `private_run_root` and a nonempty `private_source_roots` list. Run output and the shared Signal database must remain under the private run root. Existing exports, the legacy database, metrics configuration and optional media configuration must be inside the listed source roots. Direct/ancestor symlinks and linked state files are rejected. Existing timer configuration changes require a new run directory; migrate the previous configuration deliberately. The example paths are relative to the Radar repository root, which remains the documented working directory.

To enable media on a partner host, create a private media configuration from the disabled example. Set actual absolute executable/model paths, the verified resolver digest and the recorded research scope; the example is intentionally not executable. Its `private_source_root` must include the generated `signal/reels.jsonl` as well as the allowed cache/media roots. Keep raw Hiker responses in that private area and read them directly: a cache miss cannot call HikerAPI. Set both explicit enable/network flags only for the intended corpus. Run a new bounded standalone media pilot on the actual host before configuring the timer. The current macOS smoke receipts do not prove Linux readiness.

One media/model worker runs at a time, with two CPU threads, a bounded RSS watchdog and storage reserve. Videos remain retained. Missing media, empty ASR, invalid timings, failed ASR and frame outcomes remain separate. The result contains media-stage counts; `llm_calls=0` does not mean no local ASR occurred. Semantic workers must be connected through the separately reviewed task queue and an authenticated operator roster; role labels do not authenticate a server user.

The optional media dependency lock is `requirements-m2-media.txt`. Installation, frozen model acquisition and host smoke tests are explicit operator setup steps. Loore AI and paid generated inserts remain optional, independent infrastructure. Server activation is controlled by Michael; shipping code does not activate it.
