# Short-form Video Analysis Method

## Outcome

Analyze a public short-form reference as a sequence of observable decisions, then retain only clean-room abstractions that can be recombined into an original Studio framework. Never use the reference as a shot-by-shot reproduction target.

## 1. Admit the source

Register canonical URL, platform, observed time, route, rights state, retention state, and source hash/pointer before analysis. If media/frame rights are not approved, use metadata, public captions, permitted transcripts, thumbnails, and timecoded notes only. Missing access stays `GAP`; it does not become zero or negative evidence.

## 2. Segment by meaningful visual state

Create intervals for every cut, composition change, overlay change, camera move that changes attention, sound-led beat, or semantic reveal. Store millisecond start/end boundaries. Do not force a fixed frame rate into the analytical model: one record equals one meaningful visual state. The Studio library uses one-second frames only as a compact review scaffold.

## 3. Separate layers

For every interval identify:

- A-roll state: full speaker, picture-in-picture, voice-over, absent, or return cut;
- B-roll function: context, concreteness, process, proof, contrast, reset, texture, or UI orientation;
- base visual, subject/action, deterministic text, captions, proof overlay, status/footer, and audio cue;
- shot scale and movement: macro/close/medium/wide/screen/diagram plus static/pan/tilt/push/zoom/tracking;
- transition endpoints, type, and reason.

## 4. Identify the viewer job and hook

The hook is not just the first sentence. Record the first perceptible signal and the job it offers the viewer: identify a problem, assess risk, learn a mechanism, compare options, verify a claim, or imagine an outcome. Code the mechanism separately: promise, diagnostic question, contradiction, anomaly, before/after, countdown, object demonstration, consequence, reveal, or story already in progress.

## 5. Trace causal and proof logic

Map each beat as one of: tension, orientation, mechanism, proof, limitation, payoff, or exit. A proof-bearing beat must link to an observed artifact, calculation, paraphrased source, process trace, constraint, before/after observation, or worked example. Never infer causality, prevalence, or demand from high views, platform advice, a single reference, or a retention spike whose cause is unknown.

## 6. Analyze captions and audio as attention layers

Record caption onset relative to cuts (`before_cut`, `on_cut`, `after_cut`, `continuous`, `keyword_emphasis`). Captions can compete with visual inspection, so do not introduce dense new text at the same instant as a complex scene cut. Record sound role—voice anchor, pulse, accent, ambience, silence drop—and align cues to explicit boundaries. Use only licensed/original audio later.

## 7. Respect platform geometry

Use 9:16 as the master planning canvas. Keep critical content inside a conservative local inset (8% horizontal, 10% vertical), but treat that as a planning guide, not the true UI safe zone. Verify each platform's current interface and delivery format before production because controls, captions, and placements vary.

## 8. Abstract cleanly

Retain technique labels, timing relationships, shot-scale changes, proof placement, caption timing, and A-roll/B-roll functions. Exclude distinctive wording, source frames, exact layout, composition, metaphor, gesture, music, typography, branded UI, face, voice, likeness, and recognizable narrative sequence.

## 9. Recombine orthogonally

Generate a candidate from controlled taxonomy axes before writing copy. Reject exact tuple duplicates, paraphrase-only variants, and candidates with the same hook/viewer/proof/visual grammar/beat order. Require at least three changed axes among related candidates, including one semantic axis and one visual/proof/B-roll axis.

## 10. Validate and test later

Validate contiguous timing, full duration coverage, first-second hook presence, safe-zone placement, editable text, source/rights lineage, clean-room restrictions, and `external_provider_state: NOT_RUN`. Any production/performance decision must later use owned A/B testing with current platform metrics and an explicit measurement plan.

## Evidence interpretation

- FACT: official TikTok guidance emphasizes early hooks, 9:16, sound, captions, and UI-safe placement; official YouTube tools expose visual guides, timed text, multi-clip templates, and beat synchronization.
- FACT: production guidance defines B-roll as supplemental footage used for context, transitions, meaning, and jump-cut coverage.
- FACT: eye-tracking research shows cuts and subtitle timing change gaze behavior; this does not establish a universal optimal cut frequency.
- INTERPRETATION: meaningful visual changes aligned to spoken or proof beats are safer template primitives than arbitrary fast cutting.
- HYPOTHESIS: the framework taxonomy can improve creative consistency and reviewability; it does not guarantee retention, reach, or ROI.
- GAP: no rights-approved multi-platform frame corpus or owned performance experiment exists yet.
