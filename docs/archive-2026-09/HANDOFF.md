## 0. Коротко

- Источник данных — **HikerAPI**, неофициальный API к Instagram. Подключён как MCP-сервер, но
  работали мы с ним напрямую по HTTP.
- Всего сделано **~80 запросов**. **ИСПРАВЛЕНО 01.09.2026: они не были бесплатными.** Поле
  `requests` в ответе `/sys/balance` — это остаток оплаченных единиц (`amount` / $0.02),
  а не бесплатная квота. Восемьдесят вызовов стоили около $1.60. Вывод ниже про «уложились
  в бесплатный лимит» неверен; кэш экономит деньги, но сами вызовы платные.
- Собрано: 6 аккаунтов вширь (по 24 рилса на каждый), 7 роликов вглубь (видео, кадры, расшифровки),
  211 рилсов из поисковой выдачи по 18 запросам.
- Всё сырьё лежит в `data/cache/` — это ответы API как есть. Любой вывод можно перепроверить,
  **не тратя запросы**.

## 1. Решения и почему

### D1. Взяли HikerAPI, а не Apify

Прошлый датасет (ai-radar, 403 аккаунта) собирали через Apify. Причины перехода:

| | Apify | HikerAPI |
|---|---|---|
| Цена добора до 1000 аккаунтов | $28–32 | ~$2 |
| Пересылки по рилсу | нет | **есть** (`reshare_count`) |
| Сохранения по рилсу | нет | **есть** (`save_count`) |
| Просмотры | есть | есть (`play_count`) |
| Скорость итерации | запуск актора | обычный HTTP, ответ за секунды |

Решающим было не время и не цена, а **пересылки и сохранения**. Это те самые сигналы, вокруг
которых построена вся наша стратегия, и без них мы бы снова считали по лайкам — то есть по
самому слабому из модельных исходов.

### D2. Ходим curl'ом, а не через MCP-инструменты

MCP работает, но один вызов профиля выливает в контекст десятки килобайт CDN-ссылок на картинки.
Для разовой проверки это нормально, для пакетного сбора — нет. Поэтому весь сбор идёт через
`scripts/hiker.py`: обычный HTTP с заголовком `x-access-key`, ответ пишется на диск.

**Кэш обязателен.** Ключ кэша — путь плюс параметры. Любой повторный вызов с теми же аргументами
берётся с диска и не стоит ни запроса. Именно поэтому за весь день анализа мы уложились
в бесплатный лимит, хотя скрипты перезапускались десятки раз.

### D3. Аккаунты искали через поиск рилсов, а не через поиск аккаунтов

Первая попытка — `/v2/fbsearch/accounts` по ключевым словам. Результат негодный: поиск аккаунтов
в Instagram ранжируется в первую очередь по текстовому совпадению с именем, поэтому по запросу
«ai workflow» приходят `@ai_workflow95`, `@aiworkflow369`, `@a.iworkflow` — пустые аккаунты
с одинаковыми именами. 158 уникальных аккаунтов из 8 запросов, полезных — ноль.

Вторая попытка сработала: **`/v2/fbsearch/reels`** возвращает не аккаунты, а ролики, и сразу
с метриками. То есть выдача сама показывает, кто в этой теме реально получает охват. Дальше берём
авторов оттуда. Это и стало методом отбора: не «кто известен», а «кто появляется в выдаче по нашим
темам и получает там просмотры».

**Это главная методическая находка. Если будешь искать аккаунты в другой нише — начинай с поиска
рилсов, не с поиска аккаунтов.**

### D4. Всё нормируем на 1000 просмотров

Сравнивать ролик с 3 млн просмотров и ролик с 14 тысячами по абсолютным числам бессмысленно —
абсолют говорит о размере аккаунта, а не о качестве ролика. Все метрики в отчёте — пересылки,
сохранения, лайки, комментарии — приведены к тысяче просмотров.

### D5. Медиана, а не среднее

У @nateherkai из 24 роликов три сделали 1,6, 2,4 и 3,3 млн при медиане 25 тысяч. Среднее по такому
ряду — фикция. Везде, где в отчёте написано «медиана», это именно медиана.

### D6. Шесть аккаунтов вширь, семь роликов вглубь

Вширь — метрики по 24 последним рилсам, чтобы понять норму ниши. Вглубь — скачанное видео,
кадры по таймкодам и расшифровка звука, чтобы понять устройство. Ролики для глубокого разбора
отбирались по двум признакам: либо максимальный охват внутри своего аккаунта, либо максимальная
доля пересылок.

### D7. Кадры и расшифровки делаем локально

API не отдаёт ни субтитров, ни текста с экрана (проверено, см. раздел 3). Поэтому:
кадры — `ffmpeg` по URL из `video_versions`, расшифровка — `faster-whisper` модель `small` на CPU.
Всё локально, ничего не стоит.

### D8. Что из этого попало в контент-план

Три вывода, которые прямо определили сценарии:

1. **Отрицание перед покупкой даёт охват.** @leadgenman — 1 573 203 просмотра на вопросе «а нужен
   ли тебе агент». Отсюда ролик 2.
2. **Экономика внедрения — пустое место в нише.** Два независимых аккаунта на теме «сколько это
   стоит» дают 20,6 и 35,0 пересылки на 1000. Отсюда ролик 3.
3. **Интро-ролики не распространяются.** Поиск по «meet the founders», «why we started this
   company» не вернул ни одного ролика-знакомства с охватом. Поэтому ролик 1 — якорь профиля,
   а не инструмент охвата. Это решение, а не отговорка: мы сознательно не ждём от него просмотров.

### D9. Палитра взята из локального бренд-кита

Figma открыть не удалось — аккаунт упёрся в лимит обращений MCP («View seat on the Professional
plan»), расширение в Chrome не подключено. Цвета взяты из `M2 Lab — Starter Brand Kit.md`.
**Это место требует твоей проверки:** если в Figma палитра менялась после 21 августа, документ
и раскадровки надо перекрасить.

## 2. Пошаговый лог: как собирались данные

### Шаг 1. Проверка связи и первый удар по контексту

Вызов `/a2/user?username=maxtreysi`. Ответ пришёл, аккаунт живой (242 352 подписчика). Но в ответе —
последние 12 постов целиком, с полными CDN-ссылками на каждую картинку карусели. Десятки килобайт
мусора на один вызов. Вывод: этот эндпоинт для пакетной работы не годится, дальше используем
точечные.

### Шаг 2. Карта API

Скачали спецификацию: `https://api.hikerapi.com/openapi.json` (открыта, ключ не нужен).

- **154 эндпоинта**, из них **43 помечены Legacy** — их трогать нельзя, они отвечают `410 Gone`.
- Группы: профили (43), детали постов (24), поиск (14), локации (7), сторис (7), хэштеги (6),
  комментарии (5), аудио (3), системные (1).

Спецификация — самый быстрый способ понять, что вообще можно достать. Она же честно помечает,
какие эндпоинты сломаны на стороне Instagram (например, `/v1/user/web_profile_info` с февраля
2026 отдаёт ~90% ложных «UserNotFound»).

### Шаг 3. Деньги

`/sys/balance` — бесплатен, не биллится. Возвращает:

```json
{"requests": 20, "rate": 1, "currency": "USD", "amount": 0.5}
```

Разобрались опытным путём, замеряя баланс до и после одиночного вызова:

- `requests` — остаток **оплаченных единиц запроса**, то есть `amount` / цена плана.
  **Не бесплатные запросы** — это была наша ошибка, исправлена 01.09.2026;
- `amount` — деньги на счёте, догоняет `requests` с задержкой;
- цена единицы на нашем тарифе Start — **$0.02**, не $0.001;
- `rate` — лимит запросов в секунду, а не цена.

Биллинг: платят за **любой успешный ответ**, включая 400, 403 и 404. За 50x и за 410 (deprecated)
не платят. Баланс не сгорает.

> ⚠️ **Требует твоего внимания.** Наши ~80 вызовов ушли из бесплатного лимита (100 → 20), деньги
> не тронуты — это замерено напрямую. Но за день денежный баланс аккаунта сам по себе съехал
> с $2.00 до $0.50. Нашими запросами это не объясняется. Стоит проверить, не используется ли
> ключ где-то ещё.

### Шаг 4. Разведка полей: что реально приходит по рилсу

Вызвали `/gql/user/clips?user_id=...&flat=true` и распечатали ключи первого элемента. Их около
двухсот. Значимые:

| Поле | Что это | Надёжность |
|---|---|---|
| `play_count` | просмотры | приходит всегда |
| `like_count` | лайки | всегда |
| `comment_count` | комментарии | всегда |
| `reshare_count` | **пересылки** | всегда |
| `save_count` | **сохранения** | **приходит не всегда** — см. ниже |
| `1fvideo_duration` | длительность, сек | всегда |
| `1ltaken_at` | дата публикации, unix | всегда |
| `caption.text` | подпись | всегда |
| `video_versions[0].url` | прямая ссылка на mp4 | всегда, ссылка временная |
| `image_versions2.candidates` | обложка | всегда |
| `clips_metadata.original_sound_info` | id оригинального звука, автор, длительность | почти всегда |
| `is_paid_partnership` | метка рекламы | есть |
| `coauthor_producers` | соавторы (collab-посты) | есть |
| `view_count` | — | **всегда пустое, не использовать** |
| `clips_captions`, `video_subtitles_uri` | субтитры | **всегда пустое** |

Две ловушки:

1. **`view_count` пустой, работает `play_count`.** Если считать по `view_count`, получишь нули.
2. **`save_count` приходит не по каждому ролику.** У части записей поля просто нет. В отчёте такие
   помечены как «н/д», а средние по аккаунту считались только по роликам, где поле есть.
   Не заполняй нулями — занизишь.

### Шаг 5. Поиск аккаунтов: первая попытка провалилась

8 запросов в `/v2/fbsearch/accounts`: «ai workflow», «ai automation», «ai agents», «n8n»,
«ai for business», «business automation», «ai systems», «workflow automation».
158 уникальных аккаунтов. Полезных — ноль, всё это однофамильцы с пустыми профилями.
Плюс поиск аккаунтов **не отдаёт число подписчиков** — по выдаче даже отфильтровать нельзя.

Файл с результатом: `data/cand_search.json` — оставлен как иллюстрация тупика.

### Шаг 6. Поиск рилсов: то, что сработало

`/v2/fbsearch/reels?query=...` — 12 роликов на страницу, **с полными метриками**. 18 запросов
двумя заходами:

Первый заход (что делают в нише): `ai automation agency`, `ai agent for business`,
`automate business process with ai`, `n8n workflow tutorial`, `ai for operations`,
`ai sales workflow`, `lead generation automation ai`, `ai workflow`,
`business process automation ai`, `ai tools for small business` → 117 роликов, 99 авторов.
Лежит в `data/reels_pool.json`.

Второй заход (проверка наших углов): `ai automation failed`, `when not to use ai`,
`we tested ai agent`, `ai agent doesn't work`, `ai hype reality business`,
`how much does ai automation cost`, `ai replaced my employee`, `business process teardown`
→ 94 ролика. Лежит в `data/pool2.json`.

Именно второй заход доказал, что наши углы (anti-hype и экономика) в этой аудитории работают.
Это не мнение, это выдача.

Пагинация есть (`reels_max_id`), мы её не использовали — хватило первых страниц.

### Шаг 7. Снежный ком по соседям

`/v2/user/suggested/profiles?user_id=...` — **80 аккаунтов за один запрос**. Сделали от трёх сидов
(@charlieautomates, @nicholas.puru, @itsmariahbrunner).

Что дало:
- нашлись оба дуо-аккаунта ниши — @lvl_aiautomations (Lobo Brothers) и @techtalkuk;
- 13 аккаунтов попали в два соседства из трёх — это ядро ниши;
- подтвердилось, что соседство наследует язык сида (от русскоязычного сида идут русскоязычные
  соседи). Для добора RU-сегмента в будущем это ключ.

Ограничение: **подписчиков в этой выдаче нет**, только username, имя и флаг верификации.
За числами нужен отдельный запрос на каждого.

### Шаг 8. Профили

`/v1/user/by/username` — по одному запросу на аккаунт, 27 штук. Отдаёт `follower_count`,
`following_count`, `media_count`, `biography`, `category`, `is_verified`, `pk`.
`pk` дальше нужен для всех остальных вызовов. Лежит в `data/profiles.json`.

### Шаг 9. Глубокая выгрузка рилсов

`/gql/user/clips` — 12 роликов на страницу, пагинация через `max_id` из ответа. По 2 страницы
на аккаунт = 24 рилса. Шесть аккаунтов. Лежит в `data/deep.json` (метрики + подписи).

### Шаг 10. Видео и кадры

Из выгрузки берём `video_versions[0].url` и качаем `curl -sL`. Ссылки временные, но на момент
выгрузки живые. Скачано 7 роликов, от 0,8 до 29 МБ.

Кадры режет `ffmpeg`. Системного ffmpeg на машине нет и `brew` тоже — поставили статический
бинарник питоновским пакетом:

```bash
pip3 install imageio-ffmpeg
```

Он приносит с собой готовый `ffmpeg`, путь берётся из `imageio_ffmpeg.get_ffmpeg_exe()`.

Кадры брали в двух режимах: плотно в первые 3 секунды (0.4, 1.2, 2.4 с — это зона хука) и дальше
равномерно по восьмым долям длительности. Для быстрого просмотра склеивали контактные листы
фильтром `tile=5x2`. Кадры лежат в `data/frames/`, карта таймкодов — `data/frames.json`.

**Кадры оказались отдельным источником данных, а не только картинками.** У большинства роликов
субтитры вшиты в видео, и по кадрам читается и текст на экране, и композиция: где голова, где
экран, где плашка. Именно так собрана вся визуальная часть разбора.

### Шаг 11. Расшифровки

Субтитров API не даёт (проверили и `/gql/user/clips`, и `/v1/media/by/code` — все поля
`video_subtitles_*` и `clips_captions` пустые). Поэтому локально:

```bash
pip3 install faster-whisper
```

Модель `small`, `compute_type="int8"`, CPU. Семь роликов — несколько минут. Лежит
в `data/transcripts.json`, формат: `{code: {lang, segments:[{s, e, t}]}}`, где `s` — секунда начала.

Расшифровки дали два вывода, которых не было в цифрах:
- у @leadgenman (1,57 млн просмотров) **речи нет вообще** — распознавание вернуло текст песни.
  Ролик это статичная картинка под трек;
- у @whatalifeanu та же история. Оба смысла живут в подписи и в тексте на экране, не в звуке.

## 3. Что не получилось и почему

| Что | Что произошло | Обход |
|---|---|---|
| **Субтитры из API** | Поля `clips_captions`, `video_subtitles_uri`, `video_subtitles_status` пустые на всех проверенных роликах | Свой whisper локально |
| **Поиск аккаунтов по теме** | Ранжируется по совпадению с именем, отдаёт однофамильцев | Искать через поиск рилсов |
| **Подписчики в выдачах** | Ни поиск, ни «похожие аккаунты» не отдают `follower_count` | Отдельный запрос на каждого |
| **`save_count`** | Приходит не для всех роликов | Считать только по тем, где есть; «н/д» вместо нуля |
| **`view_count`** | Всегда пустой | Использовать `play_count` |
| **Демография аудитории** | В API нет вообще | Нет обхода. Только чужие публичные заявления |
| **Охваты и impressions чужих постов** | Недоступны, у нас только просмотры | Для своих будет во встроенной статистике |
| **Историческая динамика** | API отдаёт срез на момент запроса | Копить самим: гонять сбор по расписанию и складывать снимки |
| **Figma-бренд-бук** | Лимит обращений MCP на текущей подписке; расширение Chrome не подключено | Взяли палитру из локального `Starter Brand Kit.md` — **проверь** |
| **Whisper и язык** | На нигерийском акценте автоопределение выдало язык «yo» и мусорную расшифровку | Форсировать `language="en"` |
| **Python и SSL** | `urllib` падает с `CERTIFICATE_VERIFY_FAILED` на этой машине | Все запросы через `curl` из `subprocess` |
| **Конфликт имён** | faster-whisper пытался загрузить модель `small` из локальной папки `small/` (там лежали кадры) и падал | Запускать из другой директории или переименовать папку |

Отдельно: **API только на чтение**. Ничего не публикует, не подписывается, не лайкает. Это хорошо —
риска для аккаунта нет.

## 4. Как воспроизвести

Всё в этой папке. Ключ **в файл не клался** — он лежит в `~/Desktop/.mcp.json`, скрипты читают
его оттуда сами.

```
m2-research/
  scripts/
    hiker.py        # HTTP-обёртка с дисковым кэшем — база для всего
    reelsearch.py   # поиск рилсов по запросу → плоский список с метриками
    clips.py        # профиль и постраничная выгрузка рилсов
    grab.py         # скачивание видео и нарезка кадров через ffmpeg
    transcribe.py   # расшифровка звука через faster-whisper
  data/
    cache/          # 76 сырых ответов API — можно анализировать без единого запроса
    frames/         # кадры из семи роликов
    deep.json       # 6 аккаунтов × 24 рилса с метриками
    reels_pool.json # 117 рилсов из выдачи, первый заход
    pool2.json      # 94 рилса, проверка углов
    profiles.json   # 27 профилей
    transcripts.json
  report/           # сборка PDF: build.py + css.py + контент + генератор раскадровки
```

Пути внутри скриптов разрешаются относительно самого файла, поэтому запускать можно из любой
директории — кэш всегда берётся из `data/cache`, и повторный вызов не стоит ни запроса. Проверено:
оба примера ниже отработали с нуля потраченных запросов.

Установить один раз:

```bash
pip3 install imageio-ffmpeg faster-whisper pypdfium2
```
