## Cross-reference findings

FACT: the captions support nine transcript architectures: procedural walkthrough, workplace case, object-metaphor explainer, novice analogy, taxonomy explainer, character contrast, role-example/governance arc, conceptual thesis/contrast, and process-improvement explainer.

INTERPRETATION: the common reusable value is causal organization—recognizable problem, mechanism, changed state, and sometimes a boundary—not a provable visual style or performance formula.

HYPOTHESIS: original Studio packages will be easier to review when each has one forcing moment, one mechanism, one evidence object, one limitation, and one handback.

GAP: no reference supplies an admitted frame/shot map, A-roll/B-roll ratio, typography, effect timing, caption placement, edit rhythm, music/SFX, retention curve, audience context, or causal performance evidence.

## Production implications

1. Open with a recognizable forcing moment rather than a generic definition.
2. State the task before the technical mechanism.
3. Give each insert one visible evidence object.
4. Make the progression causal: problem → action/mechanism → changed state → bounded handback.
5. Reset only when the level changes: pain, mechanism, proof, limit, or CTA.
6. Limit a 6–12 second insert to one mechanism and one proof/example.
7. Make B-roll answer a narrative question.
8. Pair autonomy claims with a human decision/oversight boundary where relevant.
9. Map abstractions to an original physical/diagram model and test it with a different scenario.
10. Prefer observable transitions over speed, scale, or intelligence claims.
11. Introduce examples only after the mechanism is understood.
12. Mark illustrative scenarios as illustrative.
13. Use the CTA as a handback, not a product-style plug copied from a source.
14. Keep captions/UI editable and separate from image art.
15. Put a limitation/proof beat before payoff when the story could imply reliability, safety, or business outcomes.
