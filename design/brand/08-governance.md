# 08. Governance

Working file, not in the brand book.

For a two-person team. Keep this light. It exists so a decision does not have to
be re-made every time, not to slow the two of you down.

## Ownership

Proposed, confirm with Max: this division is not yet agreed between the two of
you.

- **Michael owns:** positioning, voice, and approval of anything that goes
  public, meaning captions, replies, collabs, sponsor copy, the profile fields.
- **Max owns:** the rendering pipeline and the technical templates, meaning the
  files and code that turn a script into a finished Reel or carousel.
- **The brand book itself (this folder) is owned jointly.** Either person can
  propose a change; follow the change process below before editing a published
  rule.
- **Visual templates** (Verdict Card, carousel layout, cover style) follow the
  same joint-ownership rule as the brand book until the two of you agree
  otherwise.

## Approval path before publishing

Run through the five questions from `06-formats.md` on every piece, in order.
Do not publish until all five are yes.

1. Can the topic and the verdict be understood with the sound off?
2. Is it recognizable as M2 with the handle hidden?
3. Is the proof ours?
4. Is a human review step named?
5. Does the closing line give an action the viewer can take alone?

Then run the copy linter from `05-vocabulary.md` against the full published
text: caption, on-screen text, script, alt text, and any reply drafted in
advance. Fix every match before publishing. A "not yet" or "we did not measure
this" is an acceptable answer; a linter match is not.

## Requesting an exception to a template

Never edit an approved template in place. If a piece needs something a
template does not allow:

1. Write down what is needed and why, as a new template proposal, not as a
   one-off tweak to the existing file.
2. Build the new version beside the approved one, under its own name.
3. Get it approved the same way any public asset is approved before using it
   on a real post.
4. Keep the original template untouched and in use until the new one is
   approved.

## How a change to the brand book happens

1. Write the proposed change and a one-line reason for it.
2. Get agreement from both Michael and Max before editing the file.
3. Add a dated entry to a changelog at the bottom of the affected file (create
   the section if it does not exist yet).
4. Keep the old rule visible in that entry as "was / became since
   `<date>`" rather than deleting it outright.

## Review cadence

- **Content rules** (`06-formats.md`, the editorial filter, cadence): review
  after every 12 publications.
- **The brand book as a whole** (positioning, voice, vocabulary, messaging,
  this file): review every 3 months, or sooner if a rule is being broken
  repeatedly in practice.

## What an agent decides alone vs. what a person approves

**An agent may, without asking:**

- Fill in the slots of an already-approved template (Verdict Card fields,
  caption structure, hashtag set) with the specifics of one piece.
- Run the five pre-publish questions and the vocabulary linter and report the
  result.
- Flag a missing human-review step, a missing number source, or a banned word
  before a person sees the draft.

**A person must approve before it goes out or takes effect:**

- Anything that becomes public: a post, caption, Reel, reply, DM template, or
  sponsor disclosure.
- Any new template, or any exception built beside an existing one.
- Any new color, type value, or other visual-system value not already in the
  approved set.
- Any change to a brand-book file, per the change process above.
